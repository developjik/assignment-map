## 본질

백엔드 과제는 돌아가는가로는 변별이 되지 않는다. 지원자의 대부분이 CRUD를 완성해서 낸다. 변별은 경계에서 난다. 검증이 컨트롤러에 흩어져 있는가 한 곳에 있는가, 실패 응답이 400 하나로 뭉개지는가 코드로 구분되는가, 동시 요청에서 데이터가 깨지는가, 그리고 심사관이 클론 받아 5분 안에 띄울 수 있는가.

DB 과제에서 상위권과 중위권을 가르는 다섯 가지가 있다. 목록 API의 N+1, 인덱스 없는 정렬, 트랜잭션 밖의 다중 쓰기, 마이그레이션 없는 스키마 변경, 시드 없는 빈 DB. 이 다섯 개를 미리 막으면 나머지 기능이 절반이어도 설계를 이해한 지원자로 읽힌다.

읽기 쉬운 코드도 채점 항목이다. 레이어를 네 개로 쪼개 놓고 파일마다 위임만 하는 구조는 감점이다. 검증, 도메인 로직, 저장소 세 층이면 충분하고, 그 세 층의 경계가 README에 한 문단으로 설명되어야 한다.

## AI 워크플로

### 1단계. 계약 문서를 코드보다 먼저 확정한다

도메인 표, 텍스트 ERD, 엔드포인트 표(메서드, 경로, 요청 본문, 응답, 상태코드, 에러코드, 인증 필요 여부)를 먼저 쓴다. 이 표가 곧 통합 테스트 목록이 된다. 표 없이 코드를 시키면 엔드포인트마다 응답 모양이 달라지고, 프론트가 없으면 그 불일치는 아무도 발견하지 못한 채 제출된다.

### 2단계. 스키마는 마이그레이션으로만 바꾸고 인덱스는 쿼리에서 역산한다

스키마 변경은 전부 마이그레이션 파일로 남긴다. 인덱스는 상상이 아니라 실제 쿼리에서 뽑는다. 정렬 컬럼, 외래키, 유니크 조합, 자주 쓰는 필터 조합 순서로 후보를 만들고 EXPLAIN 결과를 README에 한 줄씩 붙인다. 인덱스를 걸었다는 사실보다 왜 걸었는지가 점수다.

### 3단계. 경계를 한 곳으로 모은다

검증(zod, class-validator)은 라우트 진입에서 한 번, 도메인 규칙은 서비스에서, 저장소는 리포지토리에서. 에러는 도메인 에러 하나로 모으고 HTTP 매핑은 미들웨어 한 곳에서만 한다. 다중 쓰기는 트랜잭션 경계를 서비스 메서드 단위로 표시하고, 롤백되는지 테스트로 확인한다.

### 4단계. 재현성과 테스트로 마무리한다

docker compose up 한 번으로 DB, 앱, 시드가 뜨게 한다. 통합 테스트 6~10개(성공, 400, 401, 403, 404, 409, 페이지네이션 경계)를 만들고 CI에서 돌린다. README 첫 화면에 실행 3줄, API 표 링크, 설계 결정 세 개를 둔다.

## 실전 프롬프트

### 엔드포인트 계약 표

```
아래 요구사항으로 API 계약을 먼저 확정해라. 구현 코드는 아직 쓰지 마라.
표 열: 메서드 / 경로 / 인증 / 요청(필드, 타입, 검증 규칙) / 성공 응답(상태코드, 스키마) / 실패(상태코드, 에러코드) / 페이지네이션
규칙:
- 에러 코드는 도메인 단위로 이름을 붙이고 전부 나열한다
- 400과 422를 구분하는 기준을 한 줄로 명시한다
- 목록 응답의 페이지네이션 방식(offset 또는 cursor)과 정렬 기본값을 정하고 이유를 적는다
마지막에 이 표에서 빠진 결정 사항을 '가정'으로 모아라.
```

### 인덱스와 쿼리 점검

```
아래 스키마와 쿼리 목록을 보고 인덱스 후보를 제안해라.
각 후보마다: 컬럼 순서 / 대상 쿼리 / 예상 선택도 / 쓰기 비용 / 만들지 않아도 되는 이유.
그리고 N+1이 발생할 지점을 파일:라인으로 지적하고, eager loading이나 조인으로 고친 코드를 보여라.
마지막에 EXPLAIN으로 확인해야 할 쿼리 3개를 뽑아라.
```

### 통합 테스트 생성

```
아래 엔드포인트 표를 기준으로 통합 테스트를 작성해라. 실제 DB(테스트 컨테이너 또는 임시 스키마)를 쓴다.
필수: 성공 1, 검증 실패 1, 인증 없음 401, 권한 없음 403, 없는 자원 404, 중복 409, 페이지네이션 경계(빈 결과, 마지막 페이지 초과).
각 테스트는 응답 상태코드와 에러 코드, DB 최종 상태를 함께 검증한다.
테스트 간 데이터 격리 방법을 명시해라.
```

### 동시성 리뷰

```
이 서비스에서 동시 요청으로 깨질 수 있는 경로를 찾아라.
재고 차감, 중복 가입, 좋아요 토글, 동시 수정(낙관적 락 없는 업데이트)을 우선 본다.
각 경로마다: 현재 코드의 문제 / 재현 시나리오 / 해결(유니크 제약, 비관적 락, 원자적 UPDATE, 버전 컬럼) / 검증 테스트
```

## 탈락 방지

- [ ] 상태코드 표와 코드가 일치한다 (400, 401, 403, 404, 409, 422를 구분)
- [ ] 에러 응답 형태가 하나다 (code, message, details)
- [ ] 비밀번호는 해시(argon2 또는 bcrypt, cost 명시), 토큰은 만료와 갱신 정책이 있다
- [ ] 시크릿은 환경변수에만 있고 .env는 커밋되지 않는다
- [ ] 목록 API에 페이지네이션이 있고 정렬 컬럼에 인덱스가 있다
- [ ] 다중 쓰기가 트랜잭션 안에 있고 롤백 테스트가 있다
- [ ] 마이그레이션 파일이 커밋에 있고 처음부터 재생 가능하다
- [ ] 시드 데이터가 있어 첫 화면이 비어 있지 않다
- [ ] docker compose up 한 번으로 뜬다 (README에 3줄 이내)
- [ ] 통합 테스트가 CI에서 통과한다
- [ ] 입력 검증이 라우트 한 곳에 모여 있고 서비스에 중복 검증이 없다
