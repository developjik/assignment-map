## 본질

시각화 과제의 평가는 100행짜리 데모에서 이뤄지지 않는다. 심사위원은 데이터 규모를 키워 본다. 1만 포인트에서 프레임이 무너지거나, 툴팁이 축과 다른 값을 말하거나, 필터를 바꿨는데 선택 상태가 남아 있으면 그 지점에서 판단이 끝난다.

렌더 전략은 데이터 크기가 결정한다. 수백 점이면 SVG로 충분하고 인터랙션과 접근성이 쉽다. 수천에서 수만 점이면 Canvas, 그 이상은 WebGL이나 집계(다운샘플링)다. 이 결정을 README 첫 문단에 숫자와 함께 쓰는 것만으로 규모를 이해한다는 신호가 된다. 라이브러리를 골랐다면 왜 그 라이브러리이고 무엇을 포기했는지도 같이.

정보 설계도 채점 대상이다. 축 눈금이 데이터 타입과 맞는가, 0 기준선이 있는가, 색만으로 계열을 구분하고 있지 않은가, 단위가 붙어 있는가. 예쁜 차트보다 읽히는 차트가 먼저다. 그리고 빈 데이터, 전부 0, 음수, 결측값에서 축만 남은 화면이 나오는지 확인한다.

## AI 워크플로

### 1단계. 데이터를 프로파일링하고 렌더 전략을 정한다

행 수, 카디널리티, 시간 해상도, 결측과 이상치를 표로 만든다. 이 표에서 집계 단위(시간 버킷, 상위 N, 기타 묶음)와 렌더 방식(SVG, Canvas, WebGL)이 따라 나온다. 데이터를 안 보고 차트 라이브러리부터 고르면 3일째에 렌더 경로를 갈아엎게 된다.

### 2단계. 스케일과 축을 먼저 고정한다

d3-scale과 d3-array만 쓰고 DOM 조작은 직접 한다. 축, 눈금 개수, 포맷, 툴팁 문구를 먼저 정하고 정적 목업으로 확정한다. 스케일이 흔들리면 모든 인터랙션이 흔들린다. 줌과 브러시를 넣을 때도 같은 스케일 인스턴스를 공유해야 범례와 툴팁이 어긋나지 않는다.

### 3단계. 캔버스 루프와 히트 테스트를 붙인다

devicePixelRatio를 반영해 캔버스 크기를 잡고, 리사이즈에서는 스케일 재계산과 재렌더를 분리한다. 마우스 위치에서 가장 가까운 점을 찾을 때 매번 전체를 훑으면 프레임이 죽으므로 공간 인덱스나 쿼드트리를 쓴다. 렌더 루프 안에서는 setState를 부르지 않고 ref와 requestAnimationFrame으로 상태를 들고 간다.

### 4단계. 계측해서 숫자로 남긴다

10k와 100k에서 frame time, long task, 메모리를 측정해 README 표로 남긴다. 축, 툴팁, 범례가 같은 스케일과 단위를 쓰는지 체크리스트로 확인한다. 마지막으로 키보드 접근(툴팁 열기, 시리즈 토글)과 빈 데이터 화면을 붙인다.

## 실전 프롬프트

### 데이터 프로파일과 렌더 전략

```
이 데이터(<파일 경로, 스키마>)를 렌더하기 전에 프로파일링해라.
출력: 행 수 / 컬럼별 타입과 카디널리티 / 시간 해상도 / 결측 비율 / 이상치 후보 / 최대 그룹 크기
그 다음 렌더 전략 후보를 3개(SVG, Canvas, WebGL 또는 집계)로 제시하고, 각각의 예상 프레임 예산과 구현 비용을 비교해 하나를 추천해라.
추천 근거는 숫자로만 써라. 취향 표현은 쓰지 마라.
```

### 스케일과 축 고정

```
아래 차트 명세로 스케일과 축을 먼저 구현해라. 컴포넌트 렌더는 아직 하지 않는다.
- x, y 스케일 함수와 도메인 계산을 순수 함수로 분리하고 단위 테스트를 붙인다
- 눈금 개수와 포맷(천 단위, 소수 자릿수, 시간 버킷)을 데이터 타입에 맞춰 정한다
- 0 기준선이 필요한 차트인지 판단하고 이유를 한 줄로 적는다
- 줌과 브러시가 같은 스케일 인스턴스를 공유하도록 설계한다
```

### Canvas 렌더와 히트 테스트

```
Canvas로 10만 포인트 산점도를 그린다. 요구사항:
- devicePixelRatio 대응, 리사이즈 시 스케일 재계산과 재렌더 분리
- 픽셀 단위 히트 테스트 대신 공간 인덱스(쿼드트리)로 최근접 점을 찾는다
- requestAnimationFrame 루프에서 React setState를 호출하지 않는다
- 툴팁은 DOM으로 그리고, 키보드 좌우 이동으로도 열린다
- 빈 데이터와 전체 결측일 때 축만 있는 상태와 안내 문구
성능 측정 코드(frame time, p95)도 같이 넣어라.
```

### 시각화 감점 리뷰

```
이 차트 구현을 평가자 관점에서 리뷰해라. 감점 요인만, 근거 코드와 함께.
축: 타입 불일치, 0 기준선 누락, 단위 누락, 눈금 과밀
색: 색만으로 계열 구분, 대비 부족, 범례와 실제 색 불일치
상태: 선택과 필터 불일치, 리사이즈 후 툴팁 좌표 어긋남, 데이터 갱신 시 스케일 미재계산
성능: 렌더 루프 내 할당, 매 프레임 전체 순회, 불필요한 리렌더
접근성: 키보드 접근 불가, 대체 텍스트 없음
```

## 탈락 방지

- [ ] 10k 포인트 실측 프레임 타임이 README에 있다 (16ms 예산 기준)
- [ ] devicePixelRatio 대응과 리사이즈 시 재계산 비용 분리가 되어 있다
- [ ] 축 눈금이 데이터 타입에 맞고 필요한 곳에 0 기준선이 있다
- [ ] 색만으로 정보를 구분하지 않는다 (라벨, 패턴, 직접 표기 병행)
- [ ] 축, 툴팁, 범례가 같은 스케일과 단위를 쓴다
- [ ] 빈 데이터, 전부 0, 음수, 결측 케이스의 화면이 있다
- [ ] 키보드로 툴팁과 시리즈 토글에 접근할 수 있다
- [ ] 렌더 루프 안에서 setState를 호출하지 않는다 (ref와 rAF)
- [ ] 다운샘플링 기준과 근거가 코드에 있다 (LTTB 등, 임계값 명시)
- [ ] 데이터 로딩 실패 시 축만 남은 빈 차트와 안내 문구가 나온다
- [ ] 차트 이미지에 대체 텍스트나 데이터 표가 함께 제공된다
